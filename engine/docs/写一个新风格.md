# 怎么写一个新风格

照着这份写，就能做出一个能试玩、能导出、能过检查的风格。现成的例子是 `styles/001-variety-outline/`，遇到拿不准的地方直接看它。

## 1. 建文件夹

```
styles/<编号>-<英文slug>/        比如 styles/002-big-poster/
├── meta.json    参数的唯一来源（字段表见 docs/STYLE-TEMPLATE.md）
├── style.js     风格代码，导出一个 create 函数
├── STYLE.md     风格说明，按 docs/STYLE-TEMPLATE.md 的 15 节写
└── demo/        样片
```

要让导出默认用透明底（互动元素基本都是），在 meta.json 里写 `"exportDefaults": { "bg": "transparent" }`，也可以加 `"formats": ["mov", "webm"]`。

`meta.json` 至少要有：`schema`、`code`、`id`、`name`、`fonts`、`params`（里面要有 `text`、`palette`、`font`、`seed`）、`palettes`（每套正好是 8 个颜色角色：fill、fill2、inner、outer、shadow、accent、bg、sub）、`fps`、`timelineSegments`。其余字段照模板补齐，`npm test` 会检查。

## 2. style.js 的契约

```js
export function create(root, ctx) {
  // 只在这里搭 DOM / SVG：按 ctx 里的参数和画面尺寸一次搭好
  return {
    timeline,   // 表演数据：{ duration, segments:[{name,label,start,end}], beats:[{t,name,label}], units:[…] }
    layout,     // 排版结果：{ fontSize, lines, linesDetail, forced（数组，被迫拆开的长词）, issues, warnings }，检查工具要读
    seek(t) {}, // 纯函数：把这一刻所有会动的属性从头算一遍写进去
    destroy() {},
  };
}
```

宿主（`engine/src/host.js`）传进来的 `ctx`：

| 字段 | 是什么 |
|---|---|
| `params` | 解析好的完整参数。`params._palette.colors` 是 8 个颜色角色，`params._rhythm` 是节奏预设 |
| `width`、`height` | 画面尺寸（像素） |
| `fps` | 帧率：导出时是这次导出的帧率，试玩台、画廊用 `meta.fps`，都没有就是 30。按帧算时间的风格（比如估逐字时间、取整到帧）用它，不要自己写死 30 |
| `text` | 要显示的文字（已经去掉作者切分符 `\|`）。**用它，不要用 `params.text`** |
| `segment(paragraph)` | 分词函数，返回 `[{text, index}]`。来源是作者手标 → jieba+词表 → 浏览器自带分词，宿主已经按顺序选好了，风格不用管 |
| `segmentation` | 分词的原始结果和来源，排版不用，写进 layout 方便查 |
| `fontFamily(id)` | 返回这款字体的**整条字体链**的 CSS 写法（已带引号），比如 `"hanzifx-kuaile", "hanzifx-notosc-black"`。量字和写 `font-family` 都用它 |
| `beats` | 外部拍点，升序秒数数组（没有就是空数组）。要卡节拍的风格用 `motions.beatAt(t, beats)` |
| `words` | 字级时间：`[{ text, start, end }]`（秒，升序，已经加上 `--words-offset`）。拼起来去掉空白和标点等于 `ctx.text` 去掉标点（底座校验过）。没给就是空数组，风格自己决定怎么估（比如每字 0.23 秒） |
| `uid` | 每次挂载唯一的前缀，SVG 里的渐变、滤镜、遮罩 `id` 都要加上它（`${ctx.uid}-glow`），不然画廊一页放几个预览时 id 会撞 |
| `transparent` | 现在是不是透明底（导出透明素材、`npm run check`、试玩台的棋盘格都是 true）。自己画整屏底色的风格，这时要改成不画底色 |
| `background` | 背景的原值：`transparent`、`checker`、`studio`、`busy-light`、`#RRGGBB` |

## 3. 硬规矩（违反了，乱序渲染那条验收就过不了）

1. **seek(t) 只看 t**：不许依赖上一次 seek 的结果，不许累加，不许在 seek 里新建或删除元素（显示隐藏用 `visibility`）。
   - 坑：SVG 的 `visibility` 子元素能盖过父层。父层 `<g>` 设成 `hidden`，里面某个子元素上一次 seek 写了 `visibility="visible"`，它照样画出来，画面就跟上一帧有关了。子元素要显示就写 `inherit`，不写 `visible`（003 踩过：t=0 时上一帧的墨晕还留在画面上，乱序渲染第 1 帧对不上）。
2. **不许用真实时钟和随机数**：不用 `Date`、`performance.now()`、`requestAnimationFrame`、`setTimeout`、`Math.random()`。要随机就用 `engine/src/lib/rand.js` 的 `hash01(seed, '键', 序号)`，同样的参数永远得到同一个数。
3. **不许联网，不许加载风格以外的资源**：字体由宿主加载，风格只用 `ctx.fontFamily()`。
4. **零依赖**：只能 import `engine/src/` 下面的模块，不许 import npm 包。路径从 `styles/<编号>-<slug>/style.js` 往上两层就是仓库根，所以写 `import { hash01 } from '../../engine/src/lib/rand.js'`（写成三层也能跑，是因为网址往上超出根目录会停在根目录，别依赖这个）。
5. **数字写进属性前定精度**：用 `motions` 里的 `f3()`（保留 3 位小数），避免出现 `1e-7` 这种写法。
6. **不给 `<g>` 整组的透明度做动画**：透明度只设在单个图形上，入场、出场靠缩放和位移。006 和 002 开发时各自独立碰到过。2026-11-20 拿 002 加一行「出场整组淡出」复现：乱序和顺序渲染各自稳定，但两种顺序之间差 3 个像素、1 个色阶，也就是画面跟上一帧画的是什么有关。底座关掉局部重画以后照样对不上（4 种尺寸和底色 × 5 轮里有 15 次），关 GPU 光栅化、关 GPU 合成、单线程光栅化也都没用。每帧之前先画一张固定的「复位帧」能修好（`HANZIFX_RESET_FRAME=1`），但渲染要慢 25%–80%，所以没设成默认，这一条照旧是硬规矩。
7. **要旋转、倾斜的东西别带模糊滤镜（`feGaussianBlur`）**：非要模糊就让它保持不转。004 开发时实测过：每屏倾斜 2° 加模糊投影，乱序渲染有 1–3 个像素差 1 个色阶（当时是第 117、244–246、251 帧，关键词屏刚出来那几帧）；关掉倾斜或者改成不模糊的硬投影就一致了。2026-11-20 拿修复前的 004 照当时的命令（V3、透明底、4 路乱序对 1 路顺序）补测，开着局部重画和关掉各 3 轮都一致；`npm run determinism` 两种比例、两种底色各 5 轮也一致。**当时复现过，现在复现不出来**：可能那次跑的时候机器上还有别的任务，也可能是别的原因，所以照旧是硬规矩。
8. **文字不做非等比缩放**：`<text>` 和它的祖先上不要出现 `scale(x, y)` 里 x≠y 的变换（横向拉宽、竖向拉长、`textLength` 拉伸都算）。2026-11-20 在 003 抓到：印章字横向拉宽 1.35 倍，V3 停留时整体还在慢慢推近，乱序渲染偶发 1–3 个色阶的差，就在印章字边上；只把拉宽去掉，连跑 6 次就全部一致。关掉局部重画、加复位帧都管不住，像是浏览器的字形缓存跟前面几帧画过什么有关。
   - 同类的还有一种：**小字跟着整组每帧换缩放比例**。003 的印章字等比了以后，横屏 V3 停留时印章还在跟着整体推近（每帧放大一点点），印章字只有四十来像素，乱序渲染照样对不上（一块 36×36 像素，最大差 49 个色阶）。改成推近时印章只挪位置、自己不缩放，就一致了。大字（一两百像素）跟着缩放没事（001、004 的入场一直在缩放），所以这条不写成一刀切的规矩：`npm run determinism` 报到小字上，就把它挪出整组缩放、只做位移。

下面两条底座已经修了，从硬规矩降成**建议**：底座启动浏览器时默认加了 `--disable-partial-raster`（关掉「局部重新栅格化」：开着时浏览器只重画上一帧以来变了的那一块，叠在旧图块上，抗锯齿结果跟这个页面之前画过什么有关）。这两种写法在底座里已经是一致的；但换了浏览器版本、或者以后换别的渲染器（比如适配 HyperFrames），可能又会出问题，能避开就避开。风格里已经做了的绕法（隐藏、逐元素平移）留着，不用回退。

- **建议：几乎缩成一点的图形先隐藏**。从 0 开始放大的入场、缩到 0 的出场，缩放小于大约 0.2 的那几帧用 `visibility: hidden`。`bounceIn`、`popOut` 传 `minScale: 0.2`，按返回的 `visible` 显示隐藏就行。006 开发时抓到的现场：按钮刚开始入场、缩放接近 0，缩成一个点，一次画出一个透明度 7/255 的像素、一次没画出来。关掉局部重画以前 5 轮对不上 1 次，关掉以后 0 次。
- **建议：整组的亚像素平移改成逐元素平移**。005 开发时抓到的现场：每帧给整个场景那一组设 `translate(零点几像素, 0)`，横屏透明底时印章边上偶发差一两列像素，同样的渲染顺序也会偶发。关掉局部重画以前 5 轮对不上 9 次，关掉以后 0 次。005 现在把平移加进每个元素自己的 transform。

还有一种底座修不好、但很少碰到，所以只写成建议：

- **建议：动的量极小的那几帧当成没动**。008 开发时抓到的现场（V1、横屏透明底）：出场第一帧整张卡只往下挪了 0.007 像素，头像外圈边上一小条却随机出现两种画法（8 次渲染里 5 次对不上），跟乱序还是顺序无关，两种画法也都不等于上一帧。关掉局部重画、单线程光栅化、关 GPU 都没用。008 的绕法：进场的尾巴、出场的开头各留一小段死区，动的量不到 1% 就直接用停住时的值，之后再连续接上；倾斜小于 0.02 度就归零。缓动曲线的两头最容易出现这种「几乎没动」的帧，`npm run determinism` 报在入场刚停、出场刚开始的那一帧上，就先查这一条。

渲染速度：关掉局部重画以后，001 V3 演播室底 16.6 秒 → 16.4 秒（没区别），透明底 18.2 秒 → 19.4 秒（慢约 6%）。各个例子的完整对照数据见 `engine/ADR-001-渲染路径.md` 的「逐帧一致的几类坑」。

交付前跑一遍 `npm run determinism -- --style styles/<你的风格> --text "…" --set look=V3`，它会用 4 路乱序和 1 路顺序各渲染几轮、列出对不上的帧。要是撞上了，先查第 1、6、7、8 条和上面的建议；都不是的话，把命令和帧号发给底座（能复现的例子最有用）。

## 4. 能直接用的工具

- 动作（`engine/src/motions/index.js`）：`shake`、`bounceIn` 自带尾巴死区（位移不到 0.05 像素、转角不到 0.02 度、缩放差乘字号不到 0.05 像素就落到正好的静止值）；风格自己用 `spring`、`impulse`、`Math.exp` 写的衰减，尾巴要自己设死区，写法见 006、009 的 `toRest`。`bounceIn` 弹跳入场、`popOut` 缩小飞出、`wave` 波浪晃动、`jitter` 阶梯抖动、`shake` 震屏、`holdWeight` 停留段权重、`combine` 叠加、`beatAt` 查拍点、`toSvgTransform` 转成 transform 字符串；
  - 高光扫过：`shineSweep(t)` 给亮带位置，`shineStops(u)` 生成渐变色标，叠一层同形的字用这个渐变填充；
  - 数字滚动：`countUp(t, { from, to, unit: '万' })` 直接给排好的文字（12.8万、2.3亿）；`odometer(value)` 给里程表式每一位滚了多少；`formatNumber` 单独排数字；
  - 遮罩扫出：`wipe(t)` 给进度，`wipeRect` 给硬边 clipPath 的矩形，`wipeStops` 给羽化渐变遮罩的色标；
  - 墨迹晕开：`inkSpread(t, { points, maxR, seed })` 给几团边缘不规则、随时间长大的墨的路径，放进 mask，字就从墨到的地方露出来（不用 feTurbulence 滤镜，见硬规矩第 7 条）。
  演示：`engine/docs/examples/motion-demo.style.js` 是四个动作各用一次的最小写法（放进风格文件夹当 style.js 用，import 路径已按 styles/<编号>-<slug>/ 写好），可以照着抄。
- 缓动（`engine/src/lib/ease.js`）：`spring`（解析式弹簧）、`springFirstCross`（第一次到位的时刻，用来算落地节拍）、`impulse`、`easeOutCubic` 等。
- 排版（`engine/src/lib/text.js`）：`fitText`（自动字号加最佳断法：按词断、优先断在句末标点后、不留孤字、放不下就缩）、`checkLineBreaks`（卡发布的断行检查，要传同一个 `segment`）、`icuBreakWarnings`（只提示）、`FULLWIDTH_PUNCT`（标点挤压用）、`graphemes`。
- 颜色（`engine/src/lib/color.js`）：`mix(a, b, t)`。风格要更多档的颜色就从 8 个角色推，不要在配色里另起名字。

排版的写法照 001 抄：

```js
const fit = fitText(ctx.text, {
  fs0: P.size * Math.min(W, H),
  measureAt: (px) => (text) => /* 量这一块文字在 px 字号下多宽 */,
  maxWidthAt: (px) => W * 0.9 - 2 * /* 描边和动画外扩的余量 */,
  maxLines: 3, maxHeight: H * 0.8, lineHeight: 1.22,
  segment: ctx.segment,
});
// layout 里一定要带上这两项，检查工具要读：
issues: checkLineBreaks(fit.lines, ctx.text, { segment: ctx.segment }),
warnings: icuBreakWarnings(fit.lines, ctx.text),
```

`maxWidthAt` 一定要扣掉描边、厚度和弹跳过冲的余量，不然描边会被画面边缘切掉（检查会逐帧查出来）。

## 4a. 共用零件：互动元素的底座块、按键、徽章、胶囊条

互动元素里的按钮、托盘、角标、进度条，不要每个元素自己画一遍，用 `engine/src/parts/index.js` 的四个零件。每个零件有两种质感，由参数 `material` 选：

- `flat` 平面：扁平画法。013、016 原来的画法原样搬进了零件，换上零件以后逐帧一个像素都没变；
- `candy` 亮面糖果：顶面渐变、白亮边、镜面高光、往下挤出的侧壁，按下去顶面下陷、侧壁变薄，还能扫高光。一律正面朝前（不做透视倾斜：倾斜会让上面的字非等比缩放，违反第 8 条），软影子用径向渐变画（不用模糊滤镜，第 7 条）。

```js
import { createParts } from '../../engine/src/parts/index.js';
// defs 传风格自己的 <defs>；uid 用风格自己的挂载前缀（一页挂多个预览不撞）
const kit = createParts(svg, { uid, material: P.material === 'candy' ? 'candy' : 'flat', defs });

const tray = kit.slab({ x, y, w, h, radius, color: null, groove: 0.11 * u });        // 底座块：color 不给是奶白托盘；宽度会变的不给 x、w，每帧 tray.place({ x, w })
const like = kit.key({ cx, cy, w: u, h: u, color: K.fill, text: '赞', textColor: '#FFFFFF', fontFamily, fontSize });  // 方键帽
const pick = kit.key({ shape: 'circle', cx, cy, r, color: K.accent, text: 'VS', textColor: K.outer, fontFamily, fontSize }); // 圆按钮
const tag  = kit.badge({ cx, cy, w, h, color: K.fill, text: '省¥200', textColor: K.outer, fontFamily, fontSize }); // 徽章、胶囊标签
const bar  = kit.pillBar({ x, y, w, h, track: null, fill: K.fill, shineFill });        // 进度条（每帧 fillW）
const duel = kit.pillBar({ split: true, x, y, w, h, colorA: K.fill, colorB: K.fill2, shineFill }); // 对决条（每帧 splitX）
```

每帧（`seek` 里）每个零件调一次 `set`：

```js
like.set({ visible, transform, opacity, press, glow, sweep });
```

- `transform` 是整个零件的变换字符串（等比缩放、位移、旋转都行），零件把它写进自己每个元素的 transform；`opacity` 也是逐个元素写，不给整组设。
- **每次 `set` 都从默认值算**（显示、不变换、不透明、没按下、不发光、不扫光），不沿用上一帧，这样 `seek(t)` 只看 t。所以每帧要把用到的项都写上。
- `press` 0..1：顶面这一组往下挪侧壁厚度的 56.5%，顶面换成压暗的渐变，高光变弱；小于 0.05 像素的挪动当没动。`glow` 0..1：外发光和光圈（只调这两层自己的透明度）。`sweep`：直接传 `shineSweep(t, { start, duration: 0.6, width: SWEEP_WIDTH, ease: easeInOutCubic })` 的结果，一条倾斜 24° 的白带只在顶面上扫过。
- 胶囊条另有：`fillW`（进度条填充的外宽，跟平面画法一样从高度长到全宽）、`splitX`（对决条分界点）、`shine` 和 `shineSide`（风格自己的高光层显示哪边）、`dim` / `dimA` / `dimB`（输的一边变暗 0..1；平面是填充变透明，糖果是盖一层压暗，填充本身不透明，不会透出侧壁）。`bar.fillRight(fw)` 给填充右头的 x（皇冠之类挂在填充头上的东西用它）。
- 糖果质感比平面多出往下的厚度和影子：按键 `key.depth`、`key.footprint` 给出实际占地，排版和安全区要算进去。

### 把一个现有的互动元素换上零件（照这个顺序，013、016 就是这样换的）

1. **改之前先存逐帧摘要**：`npm run digest -- --style styles/<编号> --save out/digest/<编号>-before.json`（默认每个造型 × 竖屏演播室底、竖屏透明底、横屏透明底，一共导几遍 PNG，算一路渲染，要排队）。
2. 把元素里自己画按钮、胶囊、进度条的函数换成零件。**平面模式要跟原来一模一样**：元素的个数、先后顺序、每个属性的写法都不能变。原来的函数画了什么、每帧设了什么，对着 `engine/src/parts/index.js` 里 `!candy` 那几段看；零件没有的形状（013 的穿绳孔、016 的皇冠）留在元素里自己画，画的先后顺序照旧。
3. `meta.json` 加参数 `material`（`select`，选项 `flat` 平面、`candy` 亮面糖果，默认值全库统一，现在互动元素都默认 `candy`），说明文档的参数表跟着加一行。
4. **验平面**：`npm run digest -- --style styles/<编号> --compare out/digest/<编号>-before.json`，必须全部「逐帧一样」。有不一样的，先查是不是多写了一个属性、少写了一次 visibility，或者元素先后顺序变了。
5. **验糖果**：`npm run determinism -- --style styles/<编号> --set material=candy --set look=V3 --size 9:16,16:9,1:1`，日常造型也跑一遍；再出静帧，在深色和浅色画面上各看一眼。
6. 重出样片和海报。

坑：
- 糖果零件一层叠一层（影子、侧壁、顶面、高光、亮边、字），整体淡入淡出时每层各自半透明，中间那几帧会透出下面的层。淡入淡出尽量短（0.3 秒左右），主要靠缩放进出场。
- 白字压在奶白的槽上要有描边（016 的选项名、百分比本来就带深色描边）。
- 零件的 id 都带 `uid` 前缀；一个元素里放几根对决条，糖果模式每根各自一个裁切 id。平面对决条沿用 016 原来的 `${uid}-clip`，一个元素只能放一根。
- 别把零件放进一个要整体淡出的 `<g>` 里（第 6 条）。

## 5. 字体

- 在 `meta.fonts` 里写可选的主字体，在 `meta.fontFallback` 里给每款主字体写一条风格接近的备用字体链。字体必须先登记在 `engine/fonts/registry.json`（加字体的步骤见 `engine/FONTS.md`）。
- 风格里不要写死字体名，一律用 `ctx.fontFamily(P.font)`。
- 字体子集收 meta.params 里**所有 text 类型参数**的字（比如署名、印章），外加 `meta.extraGlyphs`。风格代码里写死的字（装饰字、固定标签）一定要写进 extraGlyphs，不然会被浏览器换成系统字体，导出时直接报错。
- 主字体缺的字会落到备用字体上（出警告）；整条链都没有的字，导出直接报错。
- **某个文字参数要用另一款字体**（比如 003 的印章字用思源宋体 Black，正文用书法字）：在 meta.json 写 `"paramFonts": { "seal": "notoserif-black" }`，值也可以写 `"@参数名"`，表示用那个参数选的字体。底座会把这个参数的字单独按那款字体（和它在 `fontFallback` 里的备用链）做子集、加载；风格里用 `ctx.fontFamily('notoserif-black')` 拿它的字体链。导出和试玩台走的是同一个分组函数（`engine/src/lib/params.js` 的 `fontPlan`），两边加载的字体一致。

## 5a. meta.json 里另外两个小开关

- **`allowEmpty`**：参数默认把空字符串当「没填」，退回默认值。像 003 的印章字那样「留空就不盖章」的参数，在这个参数的定义里加 `"allowEmpty": true`，空字符串才算一个值。
- **风格自己的检查**：`layout` 里可以带 `styleChecks: [{ id, level: 'warn', pass, message }]`（比如 003 的 `seal-overlap` 印章压字）。导出时没过的打 ⚠，写进 `manifest.json` 的 `checks.style`，不卡导出。`layout.issues` 只放断行问题，别把别的检查塞进去。

## 6. 自己验一遍

cd engine
npm run dev                                   # 打开 /engine/player/?style=styles/002-big-poster
