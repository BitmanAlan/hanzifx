# 风格说明模板＋ meta.json 字段表

新风格、新互动元素的 `STYLE.md` 和 `meta.json` 都照这份写。照着写，`npm test` 和 `node engine/cli/catalog.mjs --strict` 这两项 CI 检查就能过（见下面「meta.json 字段表」开头）。

这份模板以 opuscar 的 `STYLE.md` 12 节为底（只参考它的章节结构，没抄它的文字），另外规定必须有三节：「它不是什么」「坑」「可变空间」，再加上中文排版专用的几节。字效和互动元素共用这一份模板，互动元素用不上的节写「不适用」。

## 一个风格的文件夹里放什么

```
styles/<编号>-<英文 slug>/      比如 styles/002-big-poster/；还没分配编号的新风格用 styles/draft-<英文 slug>/
├── STYLE.md        风格说明，给 agent 读，也给人读（CC BY-NC 4.0）
├── meta.json       参数的唯一来源：画廊控件、调用句、检查项、README 索引表都从它生成
├── style.js        风格代码（MIT）
└── demo/           样片：竖屏 mp4（不进 git）、海报 jpg、预览动图 gif（CC BY 4.0）；用 node engine/cli/demo.mjs 按 meta.json 的 demo 生成
```

字体和公开参考效果的出处写在 `meta.json` 的 `credits` 里，不另放出处文件。

## STYLE.md 模板

规则：
- **标题固定**，编号和名字都不改。agent 靠标题跳到需要的那一节，不用整篇读完。
- 每节先写结论，再写理由。能写数字的写数字（时长写秒，大小写成占画面短边的比例），不写「适中」「合适」。
- 用不上的节写「不适用」和一句原因，不要删掉这一节。
- 全文控制在 2000 字以内。更细的东西放进 meta.json 或代码注释。

```markdown
# <编号> <中文俗名>（<English Name>）

| 编号 | 英文 slug | 中文俗名 | 曾用名 | 类别标签 | 版本 |
|---|---|---|---|---|---|
| 002 | big-poster | 大字报 | — | 封面、标题 | 0.1.0 |

一句话：<这个风格长什么样、拿来干什么，30 字以内>

调用：用 002 把「<你的字>」做成大字报，配色 C1

适合：<3 个以内的场景>　不适合：<2 个以内，写明该换哪个风格>

## 1. 本质，和它不是什么
- 本质：一句话说清这个风格靠什么成立（比如「靠字号的大小反差撑满画面」）。
- 它不是什么：列 2–4 条容易混淆的邻近风格，各写一句区别。改参数改到这一步，就该换成别的风格了。

## 2. 用在哪
平台、内容类型、画幅（竖屏 1080×1920／横屏 1920×1080／方形）、典型时长。

## 3. 画面和版式
- 位置、占画面的比例、几行几列。
- **安全区**：竖屏平台底部和右侧有按钮和文案遮挡，写明这个风格默认避开哪块。经验值是底部约 20%、右侧约 15%（没有官方规范）。
- **图层顺序**（互动元素建议照做，015 的做法）：分三层，最下面是光晕、放射光、涟漪、粒子这些装饰；中间是胶囊条、卡片和要读的字；最上面是按钮、图标、「+1」、手。三层只当容器，不加透明度也不加变换（整组透明度会让乱序渲染对不上）。这样飘的粒子和放射线永远压不到字。

## 4. 字体
- 默认字体和备选字体（只用 OFL 等允许再分发的字体，写出许可证和出处）。
- 字重、字号范围（占短边的比例）。
- 字集覆盖：这款字缺不缺常用字；缺字时怎么办（报错，不许悄悄回退到系统字体）。

## 5. 填充、描边和阴影
- 一共几层，从下到上逐层列：每层的颜色角色和宽度（占字号的比例）。
- 相邻的字，描边要不要连成一整块。

## 6. 中文排版
逐条写，用不上的写「不适用」：
- 断行：按词断，不在词中间断；一行最多几个字；不留孤字（最后一行只剩一个字）。
- 标点：行首不放标点，行尾不放开引号和开括号；全角标点挤压到多宽、在哪挤。按字的用途分两类：
  - **要读的字**（字幕、评论、说法、提示语，比如 004、009、010、012）：问号、感叹号是居中的标点，**不挤**，挤了像英文的「?」「!」。只挤这几处：行尾的逗号句号顿号、闭引号闭括号，挤掉半格；行首的开引号开括号往左挪半格，开引号开括号紧跟在别的标点后面（如「挑？（求一期）」）也一样，收掉它左边的空，前面的问号感叹号不动；两个标点连用（如「」，」），前一个挤半格。句中单个的逗号句号不挤。
  - **大字标题**（一两个词的大字，比如 001、002、011）：可以把问号、感叹号也收紧，收多少由风格自己定，粗描边的要留够，别让标点跟前一个字叠在一起（011 收到 0.7 个字宽，逗号句号挤到半格左右）。
  - 两类都要在第 6 节写明本风格挤了哪些、挤到多宽。挪多少最好按画布量出的墨迹位置算，别按固定比例：不同字体的标点墨迹位置不一样。按墨迹算有两种写法，都可以：
    - **只收一边**（010）：收尾标点收右边的空，开引号开括号收左边的空。这种写法要记得：开引号开括号在行首，或者紧跟在别的标点后面，都要收左边的空；
    - **两边一起收**（012、015）：占位宽＝墨迹宽加两边各 0.08 个字宽、至少半个字，字身左移让墨迹贴着占位左边。开括号左边的空自然就收掉了，不用另加规则。
- 中西文混排：数字和英文用什么字体，基线怎么对，前后留多少空。
- 竖排：标点放哪，引号和括号怎么转，数字和英文是立着还是躺着。
- 虚词、语气词：要不要缩小（综艺花字常把「的」「了」「吧」缩小）。

## 7. 配色预设
编号 C1、C2……，每套写名字、每个颜色角色的色值、适合什么画面。默认是 C1。

## 8. 动效：入场、停留、出场
- 每段多长（秒），用什么曲线，逐字或逐词错开多少秒。
- 节奏预设 R1、R2……（标准、快、慢），写清每个预设改了哪几项。
- 停留时动不动、怎么动。

## 9. 时间和卡点
- 跟什么对齐：字级时间戳、句子时间、音乐节拍，还是只看固定时长。
- 缺了字级时间或节拍时怎么退一步（比如按每字 0.2 秒估）。
- 海报帧取在哪个时间点（入场全部完成之后的第一帧）。

## 10. 参数和默认值
- 最常改的 3–5 个参数（完整列表看 meta.json）。
- 默认值为什么这样设：写理由，比如「字号 0.15 是 7 个字在竖屏里排成两行、左右各留 8% 时的最大值」。

## 11. 坑
写 3–6 条：哪种输入会出问题、看起来是什么样、怎么避开。最好每条都对上一条自动检查。

## 12. 可变空间
- 随便改不会坏的：<比如配色、节奏、倾斜>
- 改了会变味、要小心的：<比如描边层数降到一层>
- 改到这一步就是别的风格了：<指向哪个编号>

## 13. 检查
- 中文专项检查都要过：词中断行、行首标点、描边被裁、缺字、出了安全区。
- 乱序渲染逐帧一致：`npm run determinism` 全部一致，写明跑了哪几组、一共几次渲染。
- 本风格额外的检查：<比如「竖排引号已转成竖排字形」>

## 14. 导出和发布
- 支持的尺寸和格式（mp4、透明底 mov 或 webm、png 序列）。
- 透明底要注意什么（比如半透明的边缘、发光和阴影在透明底上是什么样）。
- 一键样片：出什么样的竖版样片，标题和文案怎么配，适合发小红书还是抖音。

## 15. 出处和许可证
- 参考的公开效果是什么（只写效果和出处链接，不拷别人的代码和素材）。
- 用到的字体及各自的许可证。
- 本说明文档用 CC BY-NC 4.0（另加做片许可），代码用 MIT，样片用 CC BY 4.0，详见 `docs/LICENSING.md`。
```

## meta.json 字段表

「必填」一列是 CI 真查的两项：
- `npm test`：必填字段在不在、8 个颜色角色齐不齐、文件夹名对不对（`<code>-<id>`，草稿是 `draft-<id>`）、预设里的参数名和取值合不合法，`params` 里要有 `text`、`palette`、`font`、`seed`，还要有 `style.js`。
- `node engine/cli/catalog.mjs --strict`（README 索引表和画廊用的字段）：`looks` 里要有标了 `role` 的日常和招牌两个预设并带英文名，还要有 `nameEn`、`status`、`summaryEn`、`platforms`，样片的动图和海报文件要在。`draft-` 文件夹还没分配编号，这一项等合并、分配编号时再查。

完整的例子：`styles/002-big-poster/meta.json`。

### 身份和名字

| 字段 | 类型 | 必填 | 说明 | 例子 |
|---|---|---|---|---|
| `schema` | 字符串 | 是 | 格式版本 | `"hanzifx.style/1"` |
| `code` | 字符串 | 是（草稿不填） | 正式编号，三位流水号，永不复用、不重排。新风格先不填，文件夹用 `draft-<id>`，合并时由维护者分配 | `"002"` |
| `id` | 字符串 | 是 | 英文 slug，也是文件夹名的后半段 | `"big-poster"` |
| `name` | 字符串 | 是 | 中文俗名，用户平时怎么叫 | `"大字报"` |
| `nameEn` | 字符串 | 是 | 英文名，英文 README 和画廊用 | `"Big Poster"` |
| `aliases` | 字符串数组 | 是（可以为空） | 曾用名和别名，用这些也能调用 | `["满屏大字", "大字封面"]` |
| `kind` | `"style"` 或 `"interaction"` | 是 | 字效还是互动元素，两种共用一套编号 | `"style"` |
| `tags` | 字符串数组 | 是 | 类别标签。编号里不带类别，类别只放这里 | `["封面", "标题"]` |
| `status` | 字符串 | 是 | `prototype`（原型可用）／`draft`（在做）／`stable`（稳定）／`deprecated`（不再维护），README 索引表的「状态」列照它写 | `"prototype"` |
| `version` | 字符串 | 是 | 这个风格自己的版本号，改了默认效果就升版本 | `"0.1.0"` |
| `tier` | 字符串 | 否 | 主仓里一律是 `"open"`，不写也按 open 算（见文末第 4 条） | `"open"` |

### 给人和 agent 看的说明

| 字段 | 类型 | 必填 | 说明 | 例子 |
|---|---|---|---|---|
| `summary` | 字符串 | 是 | 一句话说清长什么样、拿来干什么，README 索引表直接用它 | `"一段话排满画面，每行各自撑满宽度，关键词那行最大，大小反差撑起版面。"` |
| `summaryEn` | 字符串 | 是 | `summary` 的英文，英文 README 用 | `"A whole sentence fills the frame: every line stretches to full width and the keyword line is the biggest, so the size contrast carries the layout."` |
| `invoke` | 字符串 | 是 | 一句示例调用 | `"用 002 把「……」做成大字报，配色 C1"` |
| `invokeTemplate` | 字符串 | 是 | 画廊「填你的字，复制调用句」用的模板，`{text}` 会换成用户填的字 | `"用 {code} 把「{text}」做成{name}，配色 {palette}"` |
| `fitFor` | 字符串数组 | 是 | 适合的场景，3 个以内 | `["小红书封面", "观点口播开头"]` |
| `notFor` | 对象数组 | 否 | 不适合的场景，并指向该换的风格 | `[{"case": "整段口播字幕", "use": "004"}]` |
| `platforms` | 对象数组 | 是（至少一项） | 适合发哪。每项：`name` 平台和内容类型；`basis` 写 `measured`（这个风格本身在那个平台的成片里量到过）或 `inferred`（按用途推断）；`note` 写依据。README 里推断的项后面标「（推断）」 | `[{"name": "小红书封面", "basis": "inferred", "note": "按用途推断，没在小红书量过"}]` |

### 画面和时间

| 字段 | 类型 | 必填 | 说明 | 例子 |
|---|---|---|---|---|
| `sizes` | 字符串数组 | 是 | 支持的画幅 | `["1080x1920", "1920x1080", "1080x1080"]` |
| `fps` | 数字 | 是 | 帧率 | `30` |
| `durationHint` | 字符串 | 是 | 时长怎么算 | `"每行入场 0.2 秒，停留按字数算"` |
| `timelineSegments` | 对象数组 | 是 | 时间轴分段，画廊的时间轴用它分段显示 | 入场、停留、出场 |
| `posterTime` | 字符串或数字 | 是 | 海报帧取在哪：秒数、`"after-intro"`（入场完成后的第一帧）、段名，或者 `"hold+0.3"` 这类写法（见 `engine/cli/lib/when.mjs`） | `"after-intro"` |
| `safeArea` | 对象 | 是 | 默认避开的平台遮挡区，占画面的比例；`measured` 写有没有实测，`note` 写依据 | `{"bottom": 0.2, "right": 0.15, "measured": false, "note": "经验值"}` |
| `requires` | 对象 | 是 | 要不要外部输入：字级时间、音乐节拍、物体跟踪 | `{"wordTimes": false, "beats": false, "tracking": false}` |
| `exportDefaults` | 对象 | 否 | 导出时的默认值。互动元素一般默认透明底 | `{"bg": "transparent"}` |
| `measuredDefaults` | 对象 | 否 | 默认值照实测定的话，写来源和测到的数，给以后改默认值的人看 | `{"source": "成片实测，6 条样本", "y_vertical": 0.38}` |

### 字体和排版

| 字段 | 类型 | 必填 | 说明 | 例子 |
|---|---|---|---|---|
| `fonts` | 字符串数组 | 是 | 可选的主字体，键名对应 `engine/fonts/registry.json` | `["notosc-black", "huangyou"]` |
| `fontFallback` | 对象 | 建议写 | 每款主字体的备用字体链。主字体缺的字落到备用字体上（出警告），整条链都没有的字导出直接报错 | `{"notosc-black": [], "huangyou": ["notosc-black"]}` |
| `paramFonts` | 对象 | 否 | 某个文字参数要用另一款字体（比如印章字）：`{"参数名": "字体键"}`，值也可以写 `"@参数名"`，表示用那个参数选的字体 | `{"seal": "notoserif-black"}` |
| `extraGlyphs` | 字符串 | 否 | 文字参数以外、代码里写死的字（装饰字、固定标签、竖排标点），不写会被换成系统字体，导出报错 | `"！？★"` |
| `typography` | 对象 | 是 | 排版规则，检查工具按它来查 | 见下 |

`typography` 里放这些：

| 子字段 | 说明 | 例子 |
|---|---|---|
| `writingMode` | 横排还是竖排 | `"horizontal"` 或 `"vertical"` |
| `lineBreak` | 断行单位：按词、按句、手动 | `"word"` |
| `maxLines` | 最多几行 | `7` |
| `maxCharsPerLine` | 一行最多几个字 | `8` |
| `noOrphan` | 不许最后一行只剩一个字 | `true` |
| `punctCompress` | 全角标点挤压到半宽 | `true` |
| `shrinkParticles` | 虚词和语气词缩小到多少（不缩写 1） | `0.7` |
| `latinFont` | 数字和英文用哪款字体（不填就跟中文同一款） | `"jbmono-bold"` |

### 参数和预设

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `params` | 对象数组 | 是 | 每个参数：`key`、`type`（text／select／range／number／int／bool／color）、`label`、`default`、取值范围、`hint`；文字参数要能留空就加 `allowEmpty: true`。必须有 `text`、`palette`、`font`、`seed` 这四个。画廊控件全从这里生成 |
| `palettes` | 对象数组 | 是 | 配色预设 C1、C2……，每套 `{id, name, colors}`，`colors` 里 8 个颜色角色一个不少（见下表）。至少 4 套 |
| `rhythms` | 对象数组 | 否 | 节奏预设 R1、R2……，每套是一组时间参数 |
| `looks` | 对象数组 | 是 | 造型预设，每个 `{id, name, nameEn, role, aliases, params}`。至少两个：一个 `role: "default"`（日常，一般是 V1），一个 `role: "showcase"`（招牌，一般是 V3）。`params` 写这个造型改了哪些参数，参数名和取值要在 `params` 里合法 |

**颜色角色名全库统一**，同一套配色才能跨风格换用，画廊才能做「换一套配色」的按钮：

| 角色 | 意思 |
|---|---|
| `fill` | 字的主色（有渐变时是中间那一档） |
| `fill2` | 渐变的另一端 |
| `inner` | 内描边 |
| `outer` | 外描边 |
| `shadow` | 投影、厚度 |
| `accent` | 强调色：关键词、印章、装饰 |
| `bg` | 背景或底框，透明底时不用 |
| `sub` | 小字、署名、说明文字 |

### 导出、检查和出处

| 字段 | 类型 | 必填 | 说明 | 例子 |
|---|---|---|---|---|
| `exports` | 字符串数组 | 是 | 支持导出的格式 | `["mp4", "mov-alpha", "webm-alpha", "png-seq"]` |
| `checks` | 字符串数组 | 是 | 要跑哪些检查（中文专项＋本风格额外的） | `["mid-word", "line-start-punct", "line-end-punct", "stroke-clip", "missing-glyph", "safe-area"]` |
| `demo` | 对象 | 是 | 样片，`default`（日常）和 `showcase`（招牌）两条。每条写 `look`、`text`，跟 `params` 同名的键都当参数传；文件名 `video`、`gif`、`poster`（动图和海报要真的在）；可选 `posterTime`（这一条自己的海报时刻）、`canvas`（画面尺寸，默认竖屏 1080x1920）、`gifWidth`、`gifFps`、`gifMaxMB`（动图超过就自动降尺寸） | `{"default": {"look": "V1", "text": "……", "video": "demo/002_V1_日常_竖屏.mp4", "gif": "demo/preview.gif", "poster": "demo/poster-v1.jpg"}, "showcase": {…}}` |
| `extraDemos` | 对象数组 | 否 | 另外几条样片，写法跟 `demo` 里的条目一样，没写 `gif` 就不出动图 | `[{"look": "V3", "kind": "save", "video": "…", "poster": "demo/poster-save.jpg"}]` |
| `credits` | 对象数组 | 是 | 字体和公开参考效果的出处，根目录的 `NOTICE.md` 从这里生成 | `[{"what": "字体", "name": "思源黑体", "license": "OFL-1.1", "url": "…"}]` |
| `license` | 对象 | 是 | 各部分的许可证 | `{"code": "MIT", "doc": "CC-BY-NC-4.0", "demo": "CC-BY-4.0"}` |

## 规则

1. **出处只记在 meta.json 的 `credits` 里**。根目录的 `NOTICE.md` 由 `node engine/cli/notice.mjs` 从各风格的 meta.json 生成，不手改。
2. **颜色角色名全库统一**，用上面那张表的 8 个名字：fill、fill2、inner、outer、shadow、accent、bg、sub。
3. **`safeArea`（避开平台界面遮挡的区域）**：没有官方规范，先用经验值（底部 20%、右侧 15%），`measured` 写 `false`；以后实测了再改。
4. **`tier`**：主仓里的风格全部是 `"open"`。以后要是有付费风格包，用同一套格式，但不进主仓。
5. **闪烁检查 `flash-rate`**（文字快闪这类会闪的风格）：按 WCAG 2.2 的 2.3.1（Three Flashes or Below Threshold）实现：任意一秒内闪烁不能超过 3 次，除非闪烁的面积和亮度都在阈值以下。
   - 亮度阈值：一组相反方向的相对亮度变化达到 10% 或以上，并且较暗的那个状态低于 0.80，算一次普通闪烁；红色闪烁另有一条规则。
   - 面积阈值：所有同时闪烁的区域合起来，不超过视野 10° 范围的 25%。以 1024×768 屏幕为参照，10° 视野约 341×256 像素，占屏幕约 11.1%，所以同时闪的面积约占屏幕的 2.8%。实现时在画面里任取一个宽、高各是画面 1/3 的窗口，窗口里同时闪的像素不超过窗口面积的 25%，留余量取 **2.5% 画面面积**（竖屏 1080×1920 约 51,800 像素，相当于一块 228×228 的方块）。
   - **默认出安全版**，超标就不导出。安全版靠别的手段保住冲击力：每拍换字砸进画面、缩放冲击、局部闪（同时闪的面积不超过上面的阈值）、亮度不变只换色相（避开饱和红）。
   - 用户**明确打开「强闪烁」**（参数 `flashMode: "strong"`）时才允许超标。导出时打印光敏风险提示，并把超标情况写进 `manifest.json`。样片和画廊一律不用强闪烁。
