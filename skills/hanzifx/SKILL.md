# 中文字效库：给 agent 的用法

你帮用户做中文短视频里的字效和互动动效。每个风格都是一份代码：同样的输入每一帧都一样，能导出竖屏或横屏的 mp4，也能导出透明底素材（ProRes 4444 的 .mov、带 alpha 的 WebM、PNG 序列），叠到用户自己的视频上。

核心原则：**先检查再导出；检查里看到的问题照实告诉用户；没验证过的事不说成验证过。**

## 0. 环境

仓库根目录记作 `$REPO`（有 `styles/`、`engine/` 的那一层）。怎么找：这份 SKILL.md 所在目录往上两层就是 `$REPO`（软链装的，先解析成真实路径，比如 `realpath`）；如果 skill 是复制过去的，往上两层找不到 `engine/`，就问用户仓库在哪。第一次用：

```bash
cd $REPO/engine && npm install && npm run fonts && npm run doctor
```

`npm run doctor` 会一条条列出缺什么、怎么补（Node 20 以上、ffmpeg、浏览器、字体）。照它说的补，不要跳过。以后每次开工先跑一次 `npm run doctor`，几秒钟就完。

下面的命令都在 `$REPO/engine` 里跑，`--style` 写 `styles/<编号>-<名字>`。

## 1. 挑风格

```bash
node $REPO/skills/hanzifx/scripts/list-styles.mjs          # 全部风格：适合做什么、不适合（换哪个）、造型、适合发哪
node $REPO/skills/hanzifx/scripts/list-styles.mjs 004      # 一个风格的详情和全部参数
```

- 用户点了编号（「用 002」）就用那个。
- 用户只说了要做什么：照「适合」「不适合（换哪个）」挑一个，告诉他挑了哪个、为什么，直接做，不用先问。只有两个风格都很合适、而且差别很大时，才让用户选。
- 每个风格有两个造型：**默认**（日常用）和**招牌**（`--set look=showcase`，更夸张，适合封面、开头、样片）。用户说「要封面效果」「要夸张」「综艺感」时用招牌。
- 造型是一组预设参数，会盖过 meta.json 里 `params` 各项自己写的 `default`。所以判断某个效果默认开没开，要看 `looks` 里默认造型那一组，不能只看 `params`。比如 001 的 `emph` 在 `params` 里写的是 `none`，但默认造型 V1 把它设成了 `accent`，`*关键词*` 默认就会放大、换色。拿不准就跑一次检查或出一张海报看。
- 互动元素（kind 是 interaction，比如 006 三连引导）默认就是透明底。

## 2. 准备文字

- `*关键词*`：标出要突出的字，会换色、放大，有的风格会单独成屏。用户说了重点就标上；没说，就挑一个最该被看见的词标，并告诉用户标了哪个。
- `|`：作者指定能断开的地方，比如 `这也太|好笑了吧`。一般不用写，第 3 步看到切错了再加。
- 回车：分段。004 一词一屏里，回车就是**强制换屏**（`|` 只管分词，不强制换屏）；005 竖排诗句里，回车是换列。
- 文字原样保留，不要替用户改字、加标点、删语气词。

## 3. 先检查（每次都要做）

```bash
npm run check -- --style styles/002-big-poster --text "普通人用AI最大的误区，是把它当*搜索引擎*"
```

逐条读输出：

- **「分词（请看一眼切得对不对）」那一行，你必须自己看**。比如出现「工作流／程」「小／红书」「误／区」，就说明切错了：在原文里用 `|` 标出正确的断开位置，或者把这个词用 `*…*` 标住，然后重跑检查。这是中文字效好不好看的关键，别跳过。
- `✗` 是硬问题（词中间断行、标点在行首、描边被画面边缘切掉、缺字、闪烁超标）：改到没有 `✗` 再导出。缺字一般换一款字体（`--set font=…`）；描边贴边就调小字号（`--set size=…`）。
- 「提示」不卡导出（比如安全区是经验值、只剩一个字的屏），但要在交付时告诉用户。

## 4. 导出

```bash
npm run export -- --style styles/001-variety-outline --text "这也太*好笑*了吧" --out <用户的输出目录，写绝对路径>
```

常用开关：

| 要什么 | 加什么 |
|---|---|
| 叠到视频上用的透明底 | `--bg transparent`（默认导出 .mov 和 .webm）；要 PNG 序列加 `--format mov,webm,png` |
| 横屏、方形 | `--size 16:9`、`--size 1:1`；默认 9:16 竖屏 |
| 招牌造型 | `--set look=showcase` |
| 换配色、节奏 | `--palette C2`、`--rhythm R2`（有哪些看第 1 步的详情） |
| 换一种随机变化 | `--seed 8`（同一个种子永远出一样的画面） |
| 其他参数 | `--set 参数名=值`，参数名看第 1 步的详情 |

`--out` 写到用户的项目里，**用绝对路径**（相对路径是从 `engine/` 算的），比如 `/Users/…/我的项目/字效输出/001_好笑`。不要留在仓库的 `engine/out/` 里。

### 004 一词一屏：时间

- 用户给了音频或视频：先让语音识别出逐字时间（whisper、whisper.cpp、字幕软件导出的 SRT、rea-video 的结果都行），再对齐到口播稿：

```bash
node $REPO/styles/004-word-pop-captions/tools/to-words.mjs <识别结果> --text-file <口播稿.txt> --out 时间.json
npm run export -- --style styles/004-word-pop-captions --text "$(cat 口播稿.txt)" --words-file 时间.json --bg transparent --out …
```

- `to-words` 会打印对上的比例，以及哪几个字是插值出来的（识别错的字），要原样告诉用户。低于 85% 会报错：多半是口播稿跟音频不是同一段，问用户。
- 字整体早了或晚了：加 `--words-offset 毫秒`（正数往后挪）。
- 没有音频：按每字 0.23 秒估，交付时说清「时间是估的，配上真实音频的逐字时间会更准」。

### 007 文字快闪：节拍和闪烁（细节以 007 的 STYLE.md 为准）

- 要卡音乐：`--beats 0.5,1.0,…` 或 `--beats-file 拍点.json`。
- 默认是不伤眼的安全版（符合 WCAG 2.3.1，每秒闪烁不超过 3 次）。用户明确要「强闪烁」才加 `--set flashMode=strong`，并且要告诉他：画面闪得太快可能引起光敏性癫痫，发布时最好加提示。

## 5. 交付给用户

- 给出文件路径，说清每个文件是什么（成片、透明底、海报）。
- 说清检查过什么：分词怎么切的、有没有提示项。
- 照实说边界：
  - 透明底素材：照实说导出的是带透明通道的 ProRes 4444（.mov）和 VP9（.webm），要逐帧图就加 PNG 序列。不要替用户保证哪个剪辑软件一定认。
  - 安全区（平台界面会挡住的区域）现在是经验值。
  - 004 没给真实时间时，时间是估的。
- 用户做出来的视频归用户，可以商用；字体都是 OFL 许可，可以商用。

## 6. 不要做的事

- 不要仿任何平台的官方按钮、图标、品牌色和 logo（三连引导的图标都是自己画的）。
- 不要拿别人的视频画面或别人的字体去做素材。
- 不要改仓库里的风格代码来迁就某一次的需求。要改风格，那是另一件事，先告诉用户。

## 例子（也是这个 skill 的测试用例，跟 README「怎么叫」一节是同一份）

1. 用 002 把「普通人用AI最大的误区，是把它当*搜索引擎*」做成大字报，要封面效果。
2. 用 005 把「春眠不觉晓，处处闻啼鸟。夜来风雨声，*花落*知多少。」做成竖排诗句，署名「唐·孟浩然」，水墨卷轴。
3. 用 001 把「这也太*好笑*了吧」做成综艺花字，透明底，我要叠在视频上。
4. 用 004 给这段口播配一词一屏字幕，这是逐字时间文件（没有的话按语速估）。
5. 用 006 做一个三连引导，横排，透明底，放在片尾。
